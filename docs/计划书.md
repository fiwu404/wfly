# WFly 轻量多内核代理管理器计划书

## 1. 目标与边界

WFly 是一个**Windows 优先**的桌面代理内核管理器。第一版提供两个可独立下载、安装、选择和运行的官方代理内核：

- sing-box
- Xray-core

本项目只负责内核生命周期和本地配置文件的运行，不内置节点、订阅、账号或流量服务。这样既保持体积小，也让网络配置和凭据始终由用户本地掌握。

第一版运行平台为 Windows x64。内核定义、下载、校验、安装和进程托管服务与窗口界面分离；当前 Windows x64 资产规则集中在内核注册表中。后续 macOS/Linux/arm64 需要新增平台资产规则，并替换 Windows Forms 宿主界面，但可复用这套核心服务。

## 2. MVP 功能

1. 显示 sing-box 与 Xray-core 的安装状态和版本。
2. 从两者各自的 GitHub 官方 Release API 发现 Windows x64 最新稳定版并下载。
3. 下载压缩包后，以 Release API 提供的 SHA-256 摘要校验；校验失败绝不解压或执行。
4. 防 Zip Slip 解压，将内核安装到用户本地数据目录，而不是程序目录。
5. 让用户选择本地 JSON 配置文件。
6. 按内核适配器生成启动命令，启动、停止并显示标准输出/错误输出。
7. 保存最后选择的内核和配置路径；关闭软件时安全终止由本软件启动的进程。

## 3. 非目标（第一版不做）

- 不接管或修改 Windows 系统代理、TUN、DNS、防火墙或路由表。
- 不解析或托管订阅，不分发节点，不提供账号体系。
- 不静默下载或静默启动可执行文件。
- 不做自动启动、自动更新本软件、服务模式或提权安装。
- 不支持 macOS/Linux/ARM 构建产物；仅预留架构。

## 4. 技术选型

使用 .NET 8 + Windows Forms，且只依赖 .NET 标准库：

- Windows 自带桌面运行时，避免 Electron/WebView 和 npm 依赖，降低空载内存与发布体积。
- `HttpClient` 访问官方 Release API；`System.IO.Compression` 解压 ZIP；`SHA256` 校验归档。
- `System.Diagnostics.Process` 托管内核进程，异步收集日志。
- 发布为 Windows x64 单文件框架依赖程序。最终文件位于 `./release/`；内核不会被打进成品。

## 5. 架构

```text
WinForms UI
  ├─ CoreCatalogService ── GitHub Release API（只读元数据）
  ├─ CoreInstaller ─────── 下载 → SHA-256 校验 → 安全解压 → 原子安装
  ├─ CoreRegistry ──────── sing-box / Xray 的资产与命令适配
  ├─ CoreProcessService ── 启动、停止、日志、退出状态
  └─ SettingsStore ─────── 用户配置持久化

%LOCALAPPDATA%\WFly
  ├─ cores\<core-id>\<version>\   已验证内核
  ├─ state\installed-cores.json     已安装登记
  └─ settings.json                  界面选择（不保存密钥内容）
```

内核适配器为每个内核定义：官方仓库、Windows x64 资产匹配规则、可执行文件匹配规则，以及配置启动参数。将来新增内核可只新增适配器；新增平台可复用下载/校验/安装/进程管理主流程，同时为该平台提供资产规则和 UI 宿主。

## 6. 下载与安全策略

- 仅接受预置官方仓库 `SagerNet/sing-box` 与 `XTLS/Xray-core` 的正式（非 prerelease、非 draft）Release。
- 只选择严格匹配 Windows x64 ZIP 资产的文件，拒绝源代码归档和未知扩展名。
- 仅在 GitHub Release API 返回 `sha256:` 摘要时允许下载；缺少摘要即中止并明确报告，避免“下载后直接执行”。
- 将归档下载到临时目录，验证哈希后再解压；所有 ZIP 条目必须留在目标目录以内。
- 只运行已登记、已验证、且由适配器找到的 `.exe`；不接受 UI 输入的任意可执行文件路径。
- 日志会显示 URL、版本、哈希验证结果和进程输出，不记录配置文件内容。

## 7. 目录与交付物

```text
./src/                 全部源代码、解决方案、测试/说明
./release/             仅编译产物（WFly.exe、README、LICENSES）
./计划书.md             本计划书
```

运行时数据不写入上述目录，而写入 `%LOCALAPPDATA%\WFly`，从而支持非管理员运行和干净升级。

## 8. 实施步骤

1. 建立 .NET 8 WinForms 工程、核心模型和本地状态文件。
2. 实现官方 Release 发现、哈希验证、安全 ZIP 安装和安装登记。
3. 实现 sing-box/Xray 启动适配、进程托管、日志收集和停止机制。
4. 实现紧凑的单窗口界面和配置选择。
5. 编译发布到 `./release`，运行单元/自检测试，并在无内核环境下验证错误提示。
6. 为将来的平台移植补充适配说明和发布脚本参数。

## 9. 验收标准

- `dotnet publish` 成功，`./release/WFly.exe` 可在 Windows x64 启动。
- 未安装内核时，界面能明确显示状态且“启动”不可用。
- 在网络可用且官方 API 含 SHA-256 的情况下，可下载、校验、解压并登记 sing-box 或 Xray。
- 选中合法 JSON 配置后，可启动对应内核、查看日志、停止进程；退出时不遗留由 WFly 启动的进程。
- 断网、API 格式变化、无匹配资产、哈希不匹配、恶意 ZIP、无效配置路径均安全失败并给出可读提示。

## 10. 后续迭代

按优先级依次考虑：Windows arm64、配置模板与校验、导入受控本地核心、系统代理/TUN（需单独的权限与安全设计）、macOS/Linux 平台适配、签名与自动更新。
