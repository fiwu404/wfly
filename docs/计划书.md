# WFly 计划书（v0.0.3 实施版）

## 目标

构建一个轻量、Windows 优先的多内核代理客户端。第一阶段以易审计的本地控制面为主：不内置内核、不隐式改系统设置、不将运行数据写入用户目录。

## 已实施范围

### 数据与目录

- 源代码位于 `src/`，发布输出位于 `release/`。
- 所有可写运行数据位于运行程序目录下的 `./data/`，复制程序目录即可迁移。
- 旧 `%LOCALAPPDATA%\WFly` 数据仅在首次启动时安全迁移；新版本不会在那里创建数据。
- `data/` 细分为 `cores`、`profiles`、`rules`、`state`、`exports`、`temp`。

### 内核

- 固定白名单：sing-box、Xray-core、Mihomo。
- 固定 GitHub 官方仓库、Windows x64 资产规则、可执行文件名和参数。
- 必须获得 GitHub Release 的 SHA-256 摘要；流式下载、校验、受限安全解压、原子安装。

### 交互

- 右侧导航：首页、节点、节点组、连接、规则、日志、测试、设置。
- 节点仅归属节点组，不创建“全部”分类。
- 节点组可为手动空组，也可保存 HTTPS 订阅及更新间隔。
- 规则同时提供图形化表格和 JSON 文件视图。

### 运行

- 首页可启动选中节点、切换系统代理/关闭/TUN 三档模式。
- 系统代理只允许设置为本地监听端口，并使用可条件恢复的设置快照。
- TUN 由 sing-box 配置生成，需要管理员权限，程序不自行提权。
- 日志与流量样本默认仅在内存中；日志只有显式导出时才持久化。

## 后续方向

1. 完善更多订阅格式（Clash YAML、Hysteria2、TUIC、WireGuard 等）的安全解析与核心自动判断。
2. 为 Mihomo 提供图形节点到 YAML 的完整编译器，而不只依赖原生配置导入。
3. 增加经认证的 Clash API 控制器支持、连接关闭操作和更精确的流量分类。
4. 补充自动化单元/集成/UI 测试和 CI 发布流程。
5. 在用户选择许可证后补充开源许可与贡献流程。

## 安全边界

- 哈希验证传输完整性，不证明发布账户或订阅服务商一定可信。
- 订阅 URL、节点凭据和生成配置视为敏感数据，只保存在本地 `data/`。
- 外部网络访问均由用户下载、订阅更新、出口检测或站点测试操作触发；定时订阅更新仅针对用户保存且启用更新的节点组。
